# Looksy для Android

Нативное Flutter-приложение для существующего Django API Looksy. Вход/регистрация,
гардероб, камера и галерея, приватные фото, генерация образов, история,
избранное, оценки, календарь, профиль, погода и AI-стилист используют backend.
Демонстрационные данные в приложение не включены.

[Скачать Looksy 0.1.0 APK](https://github.com/AkerFer/looksy/raw/refs/heads/apk/android-0.1.0/Looksy.apk)
([страница файла на GitHub](https://github.com/AkerFer/looksy/blob/apk/android-0.1.0/Looksy.apk)).
Для закрытого репозитория сначала войдите в свой GitHub-аккаунт.

## Установка APK на телефон

1. Перенесите `app-release.apk` на Android-телефон и откройте файл. Разрешите
   установку для выбранного файлового менеджера, если Android запросит её.
2. Запустите backend по инструкции ниже. Телефон и компьютер должны быть в одной
   Wi-Fi сети. В браузере телефона проверьте `http://IP_КОМПЬЮТЕРА:8000/health/` —
   должен появиться `{"status":"ok"}`.
3. На экране входа Looksy укажите этот же адрес **без `/api/`**, например
   `http://192.168.1.5:8000`. Войдите в существующий аккаунт или зарегистрируйтесь.

`127.0.0.1` и `localhost` на телефоне обозначают сам телефон. Для стандартного
эмулятора Android Studio используйте `http://10.0.2.2:8000`.
Адрес можно сменить после выхода из аккаунта, пересборка APK не требуется.

APK содержит клиент. Django и база данных продолжают работать на компьютере
или опубликованном сервере; без доступного backend приложение не работает.
Next.js для мобильного приложения запускать не нужно.

## Backend в Windows / VS Code

В корне репозитория (там, где находятся `backend`, `frontend`, `mobile`) выполните
`ipconfig` и найдите IPv4 активного Wi-Fi адаптера. В существующем корневом `.env`
добавьте этот адрес к списку разрешённых hosts, например:

```dotenv
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.5
```

Не перезаписывайте остальные настройки `.env`. Если используется PostgreSQL
из Docker Compose проекта, сначала откройте Docker Desktop и дождитесь запуска
Docker Engine. Затем выполните в PowerShell:

```powershell
docker compose up -d --wait db
.\.venv\Scripts\python.exe backend\manage.py migrate
.\.venv\Scripts\python.exe backend\manage.py runserver 0.0.0.0:8000
```

Ошибка `psycopg.errors.ConnectionTimeout` / `connection timeout expired` означает,
что Django не смог подключиться к PostgreSQL. Для БД из Compose проекта
`POSTGRES_HOST` должен быть `127.0.0.1`, а `POSTGRES_PORT` — опубликованным портом
(по умолчанию `5432`). IP Wi-Fi компьютера указывайте в приложении и
`DJANGO_ALLOWED_HOSTS`, он не заменяет адрес PostgreSQL.

Если Docker не установлен и нужен локальный запуск с SQLite, в том же терминале:

```powershell
$env:DB_ENGINE="sqlite"
.\.venv\Scripts\python.exe backend\manage.py migrate
.\.venv\Scripts\python.exe backend\manage.py runserver 0.0.0.0:8000
```

Эта переменная действует только в текущем терминале. Для постоянного выбора
замените `DB_ENGINE=postgresql` на `DB_ENGINE=sqlite` в корневом `.env`.
SQLite использует отдельную базу: аккаунты и вещи из PostgreSQL автоматически
не переносятся. Существующие данные PostgreSQL при переключении не удаляются.

Первичная установка Python, зависимостей и БД описана в
[общей инструкции](../docs/local-setup.md). Разрешите Python входящие соединения
для **частной** сети в брандмауэре Windows. Сеть с изоляцией Wi-Fi клиентов или
VPN может мешать соединению. Компьютер и Django должны оставаться включёнными.

HTTP доступен только для тестов через loopback/частные IPv4 сети. Для сервера
в интернете приложение требует HTTPS с действительным сертификатом. Режим
Django `DEBUG=true` и `runserver` предназначены для локальной разработки.

## Сборка из исходников

Проверяемая версия: Flutter **3.44.0**, Dart **3.12.0**, Java **21**, Android SDK
platform 36 и build-tools 36.0.0. Flutter/Gradle устанавливают нужный NDK.
Установите Flutter и Android Studio, добавьте Flutter в PATH, примите Android
licenses через `flutter doctor --android-licenses`. Проверьте `flutter doctor`.

```powershell
cd mobile
flutter pub get
flutter analyze
flutter test
flutter build apk --release
```

Результат: `mobile/build/app/outputs/flutter-apk/app-release.apk`.
APK универсальный: ARMv7, ARM64, x86_64. Минимальная версия — Android 7.0
(API 24); target SDK 36. Параметры готового пакета проверяются через `aapt`.
Для подключённого по USB телефона с разрешённой отладкой:

```powershell
flutter devices
flutter run
# Или установить уже собранный APK:
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

GitHub Actions workflow `Android APK` запускает анализ, тесты, сборку и сохраняет
APK с SHA-256 в артефакте `looksy-android`. Его также можно запустить вручную
на вкладке Actions репозитория.

Эта сборка подписана **тестовым Android debug-ключом** и подходит для установки
APK напрямую. Для Google Play нужно настроить собственный постоянный release
keystore и signingConfig; приватный ключ не коммитить. Сборки с разных компьютеров
могут иметь разные тестовые подписи: для их смены Android потребует удалить
предыдущую установку. Серверные данные при этом остаются в аккаунте.

## Проверки и ограничения

```powershell
flutter analyze
flutter test
# Backend должен работать на 127.0.0.1:8000:
dart run tool/api_smoke.dart
# Можно указать другой адрес:
dart run tool/api_smoke.dart http://192.168.1.5:8000
```

Smoke-проверка создаёт временный аккаунт, вещи и фото, проверяет ротацию JWT,
генератор, избранное, оценки, календарь, профиль и удаляет временный аккаунт
вместе с данными. Она не меняет существующие аккаунты.

Refresh-токен хранится через Android Keystore / encrypted preferences; access
токен остаётся в памяти. Пароли не сохраняются. Приватные фото запрашиваются с
авторизацией, без дискового HTTP-кэша. Выход сбрасывает стек личных экранов.
Автоматический Android backup отключён. Выбранное фото может временно находиться
в приватном cache image_picker; оригинал в галерее остаётся у пользователя.
Если Android завершил процесс во время выбора фото, выберите его снова —
приложение не восстанавливает отложенное фото автоматически в другом аккаунте.

Фото проверяет backend: JPEG/PNG/WebP, 5 МБ, 16 Мп. HEIC преобразуйте в JPEG.
Сегментация и распознавание зависят от настроенных моделей backend; категорию
можно указать вручную. При ошибке AI или погоды показывается резервный ответ
или понятная ошибка. Погода требует координат города в профиле.

Тема переключается на текущий сеанс. Переписка со стилистом не сохраняется.
Офлайн-гардероб, push-уведомления и фоновые загрузки не реализованы. iOS scaffold
добавлен, но IPA и запуск на iPhone не проверялись. Камеру и галерею необходимо
дополнительно проверить на физическом Android-устройстве.
