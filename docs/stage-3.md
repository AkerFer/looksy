# Этап 3 — приватные фотографии

Реализована синхронная обработка на CPU с Pillow, OpenCV, rembg и ONNX Runtime.
Фото не отправляются внешним AI-сервисам. Категория, крой, материал и сезон
не выдумываются. Автоматическая классификация в текущей среде недоступна:
весов классификатора нет, проверка Hugging Face получила 403 от сетевого прокси.
Это ограничение классификации, а не загрузки или обработки фотографий.

## Установка и запуск

```bash
cd /workspace/looksy
.venv/bin/pip install -r backend/requirements.txt
docker compose up -d --wait db
cd backend
../.venv/bin/python manage.py migrate
../.venv/bin/python manage.py prepare_photo_model
../.venv/bin/python manage.py runserver 127.0.0.1:8000
```

prepare_photo_model скачивает небольшую модель U²-Net u2netp с официального
GitHub release rembg. Контрольная сумма взята из закреплённой версии rembg;
TLS и проверка суммы включены. Повторный запуск проверяет и переиспользует веса.
Директория по умолчанию backend/.models (исключена из Git); U2NET_HOME позволяет
задать другую. Во время загрузки пользовательского фото веса не скачиваются.

Без модели/при ошибке модели используется OpenCV GrabCut. При неудачной
сегментации сохраняется фото с фоном и возвращается предупреждение. Это не
эквивалент качеству нейросетевой сегментации. Оценка качества на реальных
фотографиях гардероба ещё не проведена.

## API

Для каждого запроса требуется JWT либо сессия. Сессионные POST/DELETE защищены
CSRF. Загрузка — multipart/form-data, ровно один файл image.

| Endpoint | Методы | Поведение |
| --- | --- | --- |
| `/api/clothing/from-photo/` | POST | Создать вещь и фото; дополнительно name и category (ID) |
| `/api/clothing/<id>/photo/` | POST, GET, DELETE | Загрузить/заменить, получить обработанное, удалить фото |
| `/api/clothing/<id>/photo/original/` | GET | Получить безопасную копию исходного изображения |
| `/api/profile/avatar/` | POST, GET, DELETE | Загрузить/заменить, получить, удалить свой аватар |
| `/api/profile/avatar/original/` | GET | Получить безопасный оригинал своего аватара |

from-photo без category создаёт вещь в «Другие вещи»; без name — «Новая вещь».
Категория модели остаётся предложением в analysis, не подменяет выбор пользователя.
category/season/colors/material/fit редактируются обычным PATCH clothing API.
Удаление фото сохраняет карточку. Удаление вещи или аккаунта удаляет записи
фотографий и их файлы. Замена фото удаляет старые файлы только после коммита БД.
Откат БД сохраняет предыдущие фото; ошибка записи нового файла очищает уже
созданные новые файлы. Сбой/прерывание процесса между файловой операцией и
коммитом может оставить сироту: перед production нужен регулярный аудит
хранилища. Ошибки удаления после коммита логируются Django и требуют повторной
очистки оператором; распределённой транзакции БД/файловой системы здесь нет.

clothing API возвращает поле photo, профиль — avatar (null при отсутствии):

```json
{
  "url": "/api/clothing/123/photo/",
  "original_url": "/api/clothing/123/photo/original/",
  "analysis": {
    "background": "u2netp",
    "recognition": {
      "status": "unavailable",
      "category": null,
      "season": null,
      "message": "Модель распознавания не установлена. Выберите категорию и сезон вручную."
    },
    "colors": [{"hex": "#294D90", "share": 0.8}],
    "warnings": [],
    "width": 1024,
    "height": 1024,
    "lighting": "preserved"
  }
}
```

Значения палитры зависят от изображения; это оценки пикселей, не точное измерение
цвета ткани. Без успешного удаления фона палитра может включать фон.
Доли относятся к видимым пикселям. Предложения не записываются автоматически
в справочник цветов или поля вещи — пользователь сохраняет выбранные значения.

## Проверка и преобразование

- Максимум 5 МБ файловых данных на запрос (проверка upload handler + повторная
  проверка в декодере), 16 миллионов пикселей, минимум 32 px по каждой стороне.
- Проверяется содержимое, не имя/заявленный MIME. JPEG, PNG, WebP; один кадр.
  SVG, GIF, анимации и повреждённые файлы отвергаются с 400.
- Проверка Pillow verify и полная декодировка; учитывается EXIF Orientation.
- Необработанные загруженные байты не сохраняются: «оригинал» — PNG с исходным
  разрешением и ориентацией, но без EXIF/GPS, ICC, комментариев и добавленных
  данных. Это намеренное отличие от побайтового хранения файла камеры.
- Обработанный предмет: удаление фона, обрезка по альфа-каналу, центрирование
  на прозрачном холсте 1024×1024 с сохранением пропорций. Аватар — 512×512,
  без удаления фона и распознавания.
- Автоматическая цветокоррекция отключена: lighting=preserved. Освещение не
  нормализуется, чтобы не менять предполагаемый цвет ткани без эталона.
- Файлы имеют случайные имена, права 0600, директории 0700. MEDIA_ROOT не имеет
  публичного URL. Не добавляйте nginx alias/static mapping на private_media.
- GET проверяет владельца родительского объекта, отдаёт image/png, nosniff,
  Cache-Control: private, no-store. Чужой ID возвращает 404. Пути хранилища не
  раскрываются в JSON. Изображение с JWT нужно загружать fetch с Authorization,
  а затем показывать через Blob URL; один публичный img src не даст авторизацию.

## Локальное распознавание

Опциональный адаптер читает только локальную доверенную модель:

```dotenv
CLOTHING_ONNX_MODEL=/absolute/path/clothing.onnx
CLOTHING_ONNX_LABELS=/absolute/path/labels.json
```

Контракт модели: один вход float32 NCHW [1,3,224,224], RGB, нормализация ImageNet,
один выход logits [1,N]. labels.json — массив N строк с названиями категорий в
порядке выходов. Подключать можно только совместимые веса с проверенным
происхождением и лицензией; произвольный ONNX/CLIP без этого контракта не подойдёт.
confidence — softmax-оценка модели, не проверенная вероятность правильности.
От 0.7 возвращается suggested; ниже — uncertain и category=null. Отсутствие
конфигурации — unavailable, ошибка загрузки/инференса — error с понятным сообщением.
Сезон/материал/фасон по недостоверной фотографии не предполагаются.
Распознавание с реальными весами классификатора ещё не проверено.

## Проверки

```bash
cd /workspace/looksy/backend
../.venv/bin/python manage.py test
../.venv/bin/python scripts/smoke_photos.py http://127.0.0.1:8000
```

HTTP smoke требует установленный u2netp и работающий сервер, создаёт временный
аккаунт, проверяет multipart, создание карточки, реальную сегментацию моделью,
приватную выдачу, отсутствие EXIF, удаление вещи и аккаунта. Для теста используется
синтетическое изображение, не личная фотография. Это проверка выполнения
конвейера, не точности распознавания и не оценка качества на одежде пользователя.

Обработка пока выполняется в HTTP-процессе; очередь, квоты диска и таймауты
инференса необходимо добавить при подготовке к нагрузке на этапе 8.

Проверено в текущей среде: 40 тестов на PostgreSQL, 14 тестов фотографий на
SQLite; миграция 0005 применена в обеих БД. HTTP smoke с реальной u2netp прошёл;
временные данные удалены. Повторная подготовка модели подтвердила checksum.
