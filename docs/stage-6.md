# Этап 6 — веб-интерфейс Looksy

Реальный Next.js frontend подключён к Django REST API. Изображения, счётчики,
списки и настройки загружаются из базы текущего пользователя. Нет seed-пользователя,
демонстрационного гардероба, захардкоженного прогноза или фиктивных ответов AI.

## Страницы и действия

- `/`: landing с CSS-иллюстрацией (декоративные силуэты, не фотографии инвентаря),
  описанием процесса, навигацией к разделам и регистрацией.
- `/register`, `/login`: регистрация и сессионный вход; понятные ошибки сервера.
- `/dashboard`: реальные счётчики, последние образы, запрос прогноза по выбранным
  координатам, переход к гардеробу и созданию образа.
- `/wardrobe`: карточки своих вещей, поиск, категория/цвет/сезон/доступность,
  сортировка и пагинация; редактирование в диалоге и удаление с подтверждением.
- `/add`: создание вещи с фото из галереи или камеры, превью до отправки,
  ручными характеристиками, цветами, комфортом/теплотой и доступностью.
- `/create`: мероприятие, стиль, комфорт, сезон, 3–5 вариантов, ручная либо
  автоматическая погода, поведение при сбое погоды, предпочтительные цвета,
  обязательные и исключённые вещи. Дополнительный текст сохраняется, но строгие
  требования нужно задавать отдельными полями — это явно подписано.
- `/results/<ids>`: результаты конкретного запроса, без смешивания с прошлой
  генерацией; сообщения backend сохраняются в generation.messages и выводятся.
- `/outfits`, `/outfits/<id>`: история, flat-lay из настоящих приватных фотографий,
  состав, критерии/объяснение, предупреждения, отметка устаревшей оценки,
  избранное, рейтинг 1–5, переход в календарь и удаление образа.
- `/saved`: избранные образы, удаление из избранного без удаления из истории.
- `/stylist`: сообщения к backend AI-адаптеру либо явный rules fallback,
  карточки существующих вещей и отдельный список недостающих категорий.
  Модель не создаёт вещи и не выполняет действия от имени пользователя.
  Переписка хранится только в памяти страницы; каждый запрос независим.
- `/calendar`: выбор месяца/дня, планирование одного образа на дату, заметка,
  обновление/удаление; всё сохраняется в БД, не в localStorage.
- `/settings`: профиль, приватный аватар, поиск/выбор города или ручные координаты,
  чувствительность к температуре, стили, цвета, крой, комфорт, исключённые
  категории и удаление аккаунта с текущим паролем/подтверждением.

Каждый видимый элемент действия выполняет запрос, навигацию, изменение формы
или темы. Нет заглушек социального входа/неработающих кнопок загрузки.
Камера использует HTML capture hint; конкретный способ выбора определяется
мобильным браузером/ОС. Параллельно доступна обычная загрузка из галереи.
При неизвестных материале/крое их можно не заполнять. Классификатор одежды
по-прежнему недоступен, это объясняется при редактировании фото; обработка фона
работает с установленной U²-Net, иначе отображаются предупреждения backend.

Если карточка сохранена, а фото загрузить не удалось, форма сообщает об этом и
повторяет запись по тому же ID, не создавая дубликат. После загрузки изображение
выдаётся через защищённый endpoint. Превью выбранного файла использует временный
Blob URL, который отзывается при смене файла/закрытии формы.

## Дизайн и доступность

Палитра из задания: cream/lavender/pink/green, округлые карточки, serif-заголовки,
минимальные иконки. В тёмной теме поверхности и текст имеют отдельные значения.
Тема — единственная сохраняемая в localStorage настройка. Анимация учитывает
prefers-reduced-motion. Мобильная навигация имеет открытие, закрытие и затемнение;
формы и сетки адаптируются. Системный dialog удерживает фокус и закрывается по Esc.
Формы имеют labels, состояния занятости и сообщения aria-live/alert. Полный аудит
WCAG/скринридеров ещё не проведён. Системный serif/font stack не требует внешней
загрузки шрифтов. Фотографии сохраняют пропорции; кадры не дорисовываются AI.

## Сессия, CSRF и приватность

Браузер ходит только на тот же origin сайта; `/api/*` проксируется Next.js в Django.
Для Django сохраняется завершающий слеш: skipTrailingSlashRedirect + destination
с завершающим `/`. Иначе редиректы Next/Django создают цикл.

Перед каждым изменяющим запросом frontend получает свежий csrfToken из session
endpoint, отправляет его вместе с cookie в X-CSRFToken. Сессионная cookie HttpOnly;
в production Django включает Secure при DEBUG=false. JWT остаётся для Flutter,
но frontend не хранит JWT/пароли/фотографии в localStorage или sessionStorage.
SSG выводит только публичную оболочку; пользовательские данные запрашиваются
с cache=no-store. Фото — обычные img через сессию и приватный endpoint, без
публичного Next Image-кэша. Backend по-прежнему проверяет владельца, а не полагается
на скрытие интерфейса. AI-текст отображается как текст React, без HTML-инъекций.

Для development доверены только http://localhost:3000 и http://127.0.0.1:3000.
Для другого origin задайте DJANGO_CSRF_TRUSTED_ORIGINS в backend-окружении и
перезапустите Django. Для публикации нужен настоящий HTTPS origin, корректные
ALLOWED_HOSTS и DEBUG=false; широкий wildcard не используется. Нельзя раздавать
backend/private_media публично. Пользовательская фотография и после удаления
аккаунта не должна кешироваться CDN.

## Backend календаря

Добавлена миграция 0008 и модель OutfitCalendarEntry: user + outfit + date + note,
FK CASCADE, уникальность user/date, индекс user/date. Общая коллекция
`/api/calendar/`, detail `/api/calendar/<id>/` поддерживает CRUD. Связанный outfit
выбирается только из своих образов; чужой ресурс → 404, чужой outfit → 400.
Удаление образа/аккаунта удаляет соответствующие планы. Дата без времени —
календарный день пользователя, без автоматического UTC-сдвига.

## Запуск

Терминал 1:

```bash
cd /workspace/looksy
docker compose up -d --wait db
cd backend
../.venv/bin/python manage.py migrate
../.venv/bin/python manage.py runserver 127.0.0.1:8000
```

Терминал 2:

```bash
cd /workspace/looksy/frontend
npm ci --cache /workspace/.npm-cache
npm run dev
```

Production-сборка для локальной проверки:

```bash
npm run typecheck
npm run build
npm run start
```

Не запускайте dev и start одновременно на одном порту 3000. BACKEND_URL задаётся
до сборки (по умолчанию 127.0.0.1:8000). Модель фото при необходимости готовится
отдельно командой prepare_photo_model из этапа 3.

## Проверки и ограничения

```bash
cd /workspace/looksy/backend
../.venv/bin/python manage.py test
cd ../frontend
npm run typecheck
npm run build
# Backend и frontend уже запущены, Chromium установлен:
npm run test:e2e
```

Браузерные проверки выполняются Chromium/Playwright против настоящих backend,
PostgreSQL и U²-Net. Ключевые действия не подменяются mocked network responses.
Тестовые учётные записи и связанные данные удаляются. Успешный inference AI и
прогноз Open-Meteo остаются непроверенными из-за ограничений этапа 5; UI показывает
эти ошибки, доступен резервный режим. Это не утверждение готовности к production.
Нагрузочные проверки, полный accessibility audit, CSP/deployment, оптимизация
длинной истории (сейчас некоторые коллекции собираются по страницам целиком) —
этап 8. Flutter — этап 7. Мобильная камера проверена как HTML input/capture,
без тестирования на физических iOS/Android устройствах.

Проверено в текущей среде: production-сборка Next.js и TypeScript прошли;
94 backend-теста на PostgreSQL, 20 проверок календаря/фото на SQLite прошли.
Оба сценария Playwright против production frontend и настоящего backend прошли,
включая замену аватара, избранное, календарь, повторный вход, предпочтения,
мобильное меню, тёмную тему и удаление аккаунта. Скриншоты результата
и мобильных настроек находятся в frontend/test-results (игнорируются Git).
Тестовые пользователи удалены. Django check и проверка миграций прошли.

Дополнительно исправлена обработка небольших фото: предмет масштабируется
до области холста с сохранением пропорций, а не остаётся маленьким в центре.
metadata фото имеет version для немедленного обновления аватара после замены;
category_slot в карточке позволяет упорядочить реальные фото в flat-lay.
Эти поля только для чтения и не открывают публичный доступ к файлам.
